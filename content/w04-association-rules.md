## 02 บทเรียนจาก feedback การนำเสนอโปรเจกต์

*(รวบรวมจาก transcript — สรุปเป็นหลักการ ไม่ไล่ทีละกลุ่ม)*

### หลักการที่ 1 — หัวข้อต้องเจาะจง ไม่ใช่ชื่อเทคโนโลยีลอย ๆ

ชื่อโปรเจกต์ที่เป็นชื่อเทคโนโลยีเฉย ๆ ถือว่า ==general== เกินไป ต้องย่อยลงมาให้เห็น domain และกลุ่มผู้ใช้ เช่นแทนที่จะตั้งว่า "Text to Speech" ให้ตั้งว่า "Thai Text-to-Speech สำหรับผู้พิการทางการพูด"

อีกจุดที่อาจารย์ชม: ทีมที่ใส่คำว่า **"พยากรณ์" / "predict"** ลงไปในชื่อ ทำให้กรรมการรู้ทันทีว่าอย่างน้อยต้องมีการสร้างโมเดล ทีมที่ไม่ใส่คำนี้ พอนำเสนอออกมามักเหลือแค่ภาพของ ==database filter==

### หลักการที่ 2 — ต้องมีโมเดล ไม่ใช่แค่ filter

ประเด็นนี้อาจารย์ย้ำกับหลายทีม: ถ้าระบบทำแค่ **data collection + filter** (ผู้ใช้กรอกเงื่อนไข → ระบบคัดรายการที่ตรงมาให้) อันนั้น**ยังไม่ถือเป็น modeling ตามแบบ data science หรือ AI**

วิธีแก้ที่อาจารย์แนะนำคือเติมส่วนที่เป็นการทำนายเข้าไป เช่น
- จาก "ค้นหาห้องเช่าตามสเปค" → เพิ่ม **regression** ทำนายราคาค่าเช่าที่เหมาะสม หรือทำนายว่าถ้าตั้งราคานี้จะปล่อยเช่าได้ภายในกี่เดือน
- หรือถ้าไม่ทำ regression ก็ใช้ **clustering** จับกลุ่มห้อง/ลูกค้าแทนก็ได้ — ขอให้มี modeling สักอย่าง
- จาก "EDA ยอดขาย" → ต้องบอกให้ชัดว่าจะ predict อะไร เช่นควรสต๊อกสินค้าแต่ละประเภทกี่เปอร์เซ็นต์

### หลักการที่ 3 — dataset ต้องมี label หรือ scoring ไม่งั้น predict ไม่ได้

**นี่คือประเด็นที่อาจารย์ย้ำหนักที่สุดในคาบ** ถ้าข้อมูลมีแต่ feature ดิบ ๆ โดยไม่มีตัวแปรเป้าหมาย (y) กำกับไว้ โมเดลจะไม่มีอะไรให้เรียนรู้

ตัวอย่างจากคาบ:
- ทีมทำนายความล้า/บาดเจ็บของนักกีฬา มี feature แค่ heart rate, HRV, step count และการนอน — อาจารย์ถามว่า **"ตัว training data ต้องมี score บอกว่าคนนี้ถือว่าเจ็บหรือเปล่า"** เพราะคน 10 คนไปเล่นเวทคนละครึ่งชั่วโมงเท่ากัน ความล้าแต่ละคนไม่เท่ากัน ต้องมี ==fatigue index== หรือ ==injury score== ตั้งแต่ต้น เทียบได้กับ credit score ที่ธนาคารใช้ตัดสินใจปล่อยกู้
- ทีมตรวจจับการล้มของผู้สูงอายุ — ต้องมีข้อมูลทั้งฝั่ง "ล้ม" และฝั่ง "ไม่ได้ล้ม" เพราะการนอนลงบนเบาะเพื่อเล่นโยคะไม่ใช่การล้ม ถ้าไม่มีคู่เทียบโมเดลก็แยกไม่ออก

> **ประโยคสำคัญของอาจารย์:** ถ้าคุณมี data แค่นั้น (ไม่มี label / ไม่มี level) สิ่งที่ทำได้มากที่สุดก็คือ ==association== หรือ ==clustering== เท่านั้น
>
> ประโยคนี้เชื่อมตรงกับเนื้อหาครึ่งหลังของคาบพอดี — association rules เป็นวิธี **unsupervised** ที่ใช้ได้แม้ไม่มี label

### หลักการที่ 4 — ต้องมี data science pipeline ที่ชัดเจน

สไลด์ต้องแสดงให้เห็นเป็นแผนภาพว่า **อะไรเข้า → เกิดอะไรใน process → อะไรออก** หลายทีมโชว์แค่ผลลัพธ์ปลายทาง อาจารย์เลยมองไม่ออกว่าโมเดลเรียนรู้ pattern อะไร

ต้องเห็นครบว่า input คืออะไร, feature engineering ทำอะไร, ใช้โมเดลอะไร (และเทียบกับโมเดลอื่นไหม เช่น logistic regression เทียบ decision tree), validation วัดด้วย metric ไหน (MAE / R²), output ที่ผู้ใช้ได้รับหน้าตาเป็นอย่างไร

### หลักการที่ 5 — tech stack ต้องระบุชัดเป็น diagram

อย่าใช้เวลาทั้งหมดไปกับ rationale ว่าทำไมควรมีโปรเจกต์นี้ ในแง่ของการ **pitch** ต้องมี concretely ว่าจะใช้อะไรเป็น tech stack: AI component ตัวไหน, agent ตัวไหน, open source ตัวไหน — และควรทำเป็น ==diagram== หรือ ==flow== พร้อมไอคอนว่า engine ตัวไหนมาเสียบตรงจุดไหน

### หลักการที่ 6 — ต้องมี reference

อาจารย์ถามหา reference แทบทุกทีม เหตุผลคือ **เวลา pitch project ถ้าไม่มี reference มันจะขาดความน่าเชื่อถือ แต่ถ้ามี reference ที่ทันสมัยจะดึงความมั่นใจจากผู้ฟังได้เยอะ**

reference ที่ควรใส่มี 3 ประเภท:
1. **Domain reference** — เว็บไซต์/แหล่งข้อมูลที่น่าเชื่อถือในโดเมนนั้น เช่นถ้าทำเรื่องการลงทุนก็อ้างเว็บการเงินที่น่าเชื่อถือ
2. **AI technology reference** — โยงไปที่เว็บไซต์ของเครื่องมือ/โมเดลที่เอามาใช้
3. **งานที่คนอื่นทำไว้แล้ว** — Kaggle notebook ที่ศึกษามา, บทความ Medium, published paper ที่ค้นเจอ

### หลักการที่ 7 — หาจุดต่างของเรา ไม่ต้องทำทุกอย่าง

ถ้าเรื่องที่ทำมีคนทำอยู่แล้ว (โดยเฉพาะในไทย) ให้ไปดูว่าเขาทำอะไรอยู่ แล้วชี้ให้ชัดว่า**เราจะปรับตรงไหนให้ต่างจากเขา** อาจารย์ย้ำว่า "**ไม่จำเป็นต้องทำทุกอย่าง** ขอให้มีตัวที่คนอื่นยังไม่ทำ เพราะเวลาเราสั้น"

### หลักการที่ 8 — scope ต้องเขียนไว้ตั้งแต่ requirement

ข้อจำกัดต่าง ๆ ต้องไม่ใช่แค่หน้า "Limitation" ท้ายสไลด์ แต่ต้องเขียนไว้ตั้งแต่ requirement ตอนแรก ตัวอย่างการ scope ที่อาจารย์แนะนำ:
- รับเฉพาะ comment ภาษาอังกฤษ, จำกัดจำนวน comment ต่อคลิป, จำกัดความยาว comment
- เลือก **hardware platform เดียว** ไม่ต้องรองรับหลายยี่ห้อ (เพราะ sensor แต่ละยี่ห้อ calibrate ต่างกัน) — ในสโคปวิชานี้ hardware data source เดียวก็พอ
- ทำสินค้าแค่ ~30 ชิ้นในร้านหนังสือ มจธ. แทนที่จะพยายามครอบคลุมสินค้าเป็นพันชิ้นในร้านสะดวกซื้อ

เหตุผล: **"อันนี้เป็นแค่โปรเจกต์ใน class เล็ก ๆ ไม่ใช่ commercial เราแค่ทดสอบไอเดีย"**

### หลักการที่ 9 — ทุกทีมต้องตอบได้ว่าจะทดสอบอย่างไร

อาจารย์บอกว่า **"ทุกทีมต้องลองนึกแล้วว่าจะมาบอกอาจารย์ว่ามันทำแล้ว success 70% 80% ได้ยังไง"** ต้องมี test case และต้องรู้ว่าจะแบ่ง ==train/test== อย่างไร (ซึ่งเป็นเรื่องที่ อ.พรชัยจะสอนใน data science)

เกร็ดเสริม: ถ้า dataset ที่หยิบมาจาก Kaggle เป็นโปรเจกต์ที่ยัง live อยู่ จะมี ==live scoreboard== ให้ submit โมเดลขึ้นไปแล้วได้ accuracy กลับมาทันที ทำให้พัฒนาได้เร็วขึ้นมาก — ให้ไปเช็กว่า dataset ของทีมตัวเองมีหรือเปล่า

### หลักการที่ 10 — การเก็บและคุณภาพของข้อมูล

- **สุ่มอย่าเลือก** — ถ้าข้อมูลจริงมีเป็นแสนแถวแล้วจะย่อลงมา ให้ ==random sample== อย่าเลือก top-N เพราะการสุ่มจะรักษาพฤติกรรมตามความเป็น randomness ของข้อมูลไว้
- **เก็บให้หลากหลาย** — โปรเจกต์ที่ใช้ภาพ ต้องเก็บหลายมุม หลายสภาพแสง หลายสภาพอากาศ (เช้าแดดย้อน / ฝนตก) และถ้าเป็นไปได้ควรมีภาพจากบริบทไทยด้วย ไม่ใช่ใช้แต่ dataset ต่างประเทศ
- **จริยธรรมการเก็บข้อมูล** — การเก็บ dataset ที่ต้องให้คนมาแสดงพฤติกรรมจริง (เช่น ล้ม) ในงานวิจัยต้องยื่นขอ ==IRB== จากมหาวิทยาลัยก่อน แล้วจึงหา volunteer ถ้านักศึกษาไม่ได้ขอ IRB ให้ระวังตัวเองมาก ๆ หรือเปลี่ยนไปใช้ dataset สาธารณะแทน
- **PDPA** — ข้อมูลสุขภาพและข้อมูลชีวมาตร (biometric) ถือเป็น ==ข้อมูลอ่อนไหว== ตาม PDPA จึงเก็บได้ยาก ต้องคิดเผื่อไว้

### หลักการที่ 11 — คิดถึงเงื่อนไขในโลกจริง

- **ทำนายให้ทันเวลาที่จะแก้ไข** — ทีมทำนายการลาออก อาจารย์ชี้ว่าตามกฎหมายพนักงานต้องยื่นใบลาออกล่วงหน้าอย่างน้อย 30 วัน ดังนั้นถ้าโมเดลบอกตอนที่เขายื่นไปแล้วก็สายเกินไป ต้องออกแบบให้ predict ความเสี่ยงล่วงหน้า **2 เดือน**
- **ความปลอดภัยและ redundancy** — อุปกรณ์ที่ช่วยคนตาบอดสีอ่านสัญญาณไฟจราจร ถ้าเป็นของจริงต้องมีมากกว่าหนึ่ง device เพราะถ้าเครื่องเดียวแบตหมดกลางทางจะกลายเป็นอันตราย ในสโคปวิชานี้ให้ถือเป็น ==prototype==
- **ราคา/ข้อมูลที่เปลี่ยนตามเวลา** — ระบบเช็กราคาสินค้า ต้องรู้ว่าราคา standard (UPC) อาจไม่ใช่ราคาจริงในวันนั้น เพราะร้านลดราคาเฉพาะสัปดาห์ได้ ทางแก้ในสโคปคือ fix ราคาไว้ก่อน

### หลักการที่ 12 — การออกแบบสไลด์

- ตัวหนังสือ**ใหญ่ขึ้น** กราฟิก**น้อยลง** เน้นข้อความหรือ diagram ให้ชัด และใช้พื้นที่ในสไลด์ให้เหมาะสม
- **อย่าไว้ใจ AI จนเกินไป** — สไลด์ที่ generate ด้วย AI มักแน่นเกินกว่าที่คนจะอ่านทัน ทำให้ presentation ไม่ effective ต้องเอามาเบรกเองเป็นหน้า ๆ (เช่น แยกหน้า data preprocessing ออกจากหน้า modeling)
- ดูตัวอย่าง **sample project** ที่อาจารย์โพสต์ไว้ (เป็นภาษาอังกฤษ) จะเห็นว่าเขาพูดถึง use case และ engine ที่เลือกใช้ชัดเจน

## 04 Association Rules คืออะไร

==Association rules== (หรือ ==association mining==) คือการสร้าง **กฎความสัมพันธ์** จากข้อมูล เขียนในรูป **if–then**

```
X → Y     อ่านว่า "ถ้ามี X แล้ว มีโอกาสที่จะมี Y ด้วย"
```

- **X** เรียกว่า ==antecedent== (ฝั่งซ้าย / left-hand side) — เป็นเซตของ item ตั้งแต่ 1 ตัวขึ้นไป
- **Y** เรียกว่า ==consequent== (ฝั่งขวา / right-hand side) — เป็นเซตของ item ตั้งแต่ 1 ตัวขึ้นไป
- X และ Y ต้อง ==disjoint== คือไม่มี item ซ้ำกันเลย

รูปแบบของกฎที่เป็นไปได้ (จากสไลด์หน้า 16):

```
A ∧ B → C
A ∧ C → B
B → A ∧ C
...
```

**Market Basket Analysis (MBA)** คือเทคนิค data mining ที่ใช้หาความสัมพันธ์ของสินค้าที่ถูกซื้อพร้อมกันบ่อย ๆ เป้าหมายคือขุดหา hidden pattern ในข้อมูลธุรกรรมแล้วเขียนออกมาเป็น association rules

> *(จาก transcript)* วิธีจำชื่อของอาจารย์: MBA ตัวเดียวกับปริญญาโท Master of Business Administration ที่คนไทยสมัยก่อนชอบไปเรียนต่อกัน แต่ในวิชานี้คือ **Market Basket Analysis**

> *(จาก transcript)* **เรื่องเล่า beer & diapers** — มีการค้นพบจากข้อมูลฝั่งอเมริกาว่าผู้ชายที่ไปช้อปปิ้งช่วงเย็นวันศุกร์ ซื้อเบียร์แล้วมักจะซื้อผ้าอ้อมเด็กไปด้วย ตีความได้ว่าเป็นกลุ่มคนที่แต่งงานมีลูกเล็ก มาซื้อของให้ลูกไปพร้อมกับซื้อเบียร์ไว้ดูกีฬาของตัวเอง — เดิมทีคนคิดว่าผ้าอ้อมน่าจะเป็นแม่บ้านซื้อมากกว่า นี่คือตัวอย่างของ **pattern ที่ซ่อนอยู่และไม่มีใครคาดคิด** ซึ่งเป็นสิ่งที่ MBA ต้องการขุดหา

## 06 Item, itemset และ frequent itemset

- ==Item== = สินค้าหนึ่งประเภท เช่น Milk, Bread, Butter, Eggs, Diapers
- ==Itemset== = กลุ่มของ item ตั้งแต่ 1 ตัวขึ้นไปที่ปรากฏด้วยกันใน transaction เดียว
  - **1-itemset** เช่น {Milk}
  - **2-itemset** เช่น {Milk, Bread}
  - **3-itemset** เช่น {Milk, Bread, Butter}
- ==Frequent itemset== = itemset ที่ปรากฏใน database ของ transaction **มากกว่าหรือเท่ากับ ==minimum support threshold==** ที่ผู้ใช้กำหนด

*(จาก transcript)* จุดที่อาจารย์อธิบายเพิ่ม:
- **1-itemset อย่างเดียวใช้สร้างกฎไม่ได้** เพราะการมีสินค้าประเภทเดียวไม่ได้บอกความสัมพันธ์กับสินค้าอื่น ต้องมีอย่างน้อย 2-itemset
- ในทางปฏิบัติ **3–4 itemset กำลังพอดี** ถ้าเกิน 5 ขึ้นไปจะสับสน หา pattern ยาก และไม่มีประโยชน์ ส่วนใหญ่โจทย์จะจบกันที่ 3 หรือ 4 itemset
- คำว่า **frequency** คือจำนวนครั้งที่ itemset นั้นปรากฏ ยังไม่ได้หารด้วยอะไร ส่วน **support** คือ frequency ที่หารด้วย N แล้ว

## 07 Apriori algorithm และ Apriori property

==Apriori algorithm== เสนอครั้งแรกโดย **Rakesh Agrawal และ Ramakrishnan Srikant ในปี 1994** ใช้หา frequent itemset และผลิต association rules ออกมา

*(จาก transcript)* ชื่อ "Apriori" มาจากความหมายว่า **"สิ่งที่เกิดขึ้นก่อน"** — คือใช้สิ่งที่รู้จากรอบก่อนหน้ามาช่วยตัดสินใจในรอบถัดไป (อ่านออกเสียงได้หลายแบบ ไม่ต้องซีเรียส)

### Apriori property มี 2 ข้อ

**ข้อ 1 — ถ้า itemset ใด frequent แล้ว ทุก subset ของมันก็ต้อง frequent ด้วย**

ตัวอย่างจากสไลด์: ถ้า {Bread, Butter, Milk} frequent (คือถูกซื้อพร้อมกันบ่อย) แล้วโดยตรรกะ subset ทั้งหมดของมัน คือ {Bread, Butter}, {Butter, Milk}, {Bread, Milk}, {Bread}, {Butter}, {Milk} ก็ต้อง frequent ด้วย

**ข้อ 2 (contrapositive) — ถ้า itemset ใดไม่ frequent แล้ว ทุก superset ของมันก็ไม่ frequent ด้วย**

ตัวอย่างจากสไลด์: ถ้าอัลกอริทึมพบว่า itemset เล็ก ๆ อย่าง {Beer, Chips} ไม่ frequent ก็สามารถ ==prune== (ตัดทิ้ง) itemset ที่ใหญ่กว่าซึ่งมี {Beer, Chips} อยู่ข้างในได้ทันที

*(จาก transcript)* อาจารย์โยงกลับไปที่วิชา Discrete Mathematics: กฎข้อ 2 คือ ==contrapositive== ของกฎข้อ 1 พอดี

```
p → q   สมมูลกับ   ¬q → ¬p
```

จึงแทบไม่ต้องจำอะไรใหม่เลย — กฎข้อ 2 คือกฎข้อ 1 สลับข้าง

### ทำไมต้องมี pruning

*(จาก transcript)* เพราะในความเป็นจริงร้านค้ามีสินค้าเป็นพันเป็นหมื่นประเภท ถ้ามี item n ตัว จำนวน subset ทั้งหมด (power set) จะเป็น **2ⁿ** — ถ้า n = 1,000 ก็คือ 2^1000 ซึ่งคำนวณไม่ไหวเลย

Apriori จึงใช้กฎข้อ 2 ตัดทิ้ง: **อะไรที่ไม่ frequent ก็โยนทิ้ง ไม่ต้องไปขยายต่อ** ประหยัดเวลาการคำนวณมหาศาล

### ขั้นตอนการทำงาน

```
1. หา 1-itemset ทั้งหมด → คำนวณ support → ตัดตัวที่ต่ำกว่า min support ทิ้ง
2. จับคู่เฉพาะตัวที่เหลือ เป็น 2-itemset → คำนวณ support → ตัดทิ้งอีกรอบ
3. จับกลุ่มเฉพาะตัวที่เหลือ เป็น 3-itemset → คำนวณ support → ตัดทิ้งอีกรอบ
4. วนไปเรื่อย ๆ จนไม่เหลือ itemset ที่ผ่านเกณฑ์ แล้วหยุด
5. เอา frequent itemset ที่เหลือทั้งหมดไปสร้าง association rules ด้วย confidence
```

## 08 Support

==Support== ตอบคำถามว่า **"itemset นี้ popular แค่ไหน"**

$$\text{Support}(X) = \frac{\text{จำนวน transaction ที่มี } X}{\text{จำนวน transaction ทั้งหมด}}$$

- มีค่าตั้งแต่ **0% ถึง 100%**
- ==Minimum support threshold== คือค่าขั้นต่ำที่ผู้ใช้ตั้งไว้เอง อะไรที่ต่ำกว่านี้ถือว่า infrequent → **discard** ทิ้ง

ตัวอย่างจากตาราง 5 transaction ข้างบน:
- Support({Milk}) = 4/5 = **80%** (ปรากฏใน T1, T2, T4, T5)
- Support({Milk, Diapers}) = 2/5 = **40%** (ปรากฏใน T2, T5 เท่านั้น)

*(จาก transcript)* **อาจารย์ย้ำว่าเวลาสอบต้องจำสูตร support และ confidence ให้ได้** เพราะข้อสอบจะไม่ให้สูตรมา ต้องเขียนสูตรเองได้

## 09 Confidence

==Confidence== ตอบคำถามว่า **"ถ้ามี X แล้ว บ่อยแค่ไหนที่มี Y อยู่ด้วย"**

$$\text{Confidence}(X \rightarrow Y) = \frac{\text{Support}(X, Y)}{\text{Support}(X)}$$

โดย Support(X, Y) หมายถึง support ของกรณีที่ **X และ Y เกิดขึ้นพร้อมกัน** (X ∧ Y)

*(จาก transcript)* วิธีจำของอาจารย์: confidence เป็น**เงื่อนไข** — "ถ้ามี X แล้ว Y จะเกิดขึ้นไหม" ดังนั้น **X ต้องเกิดขึ้นก่อน** จึงเอา X ไปเป็นตัวหาร ส่วนตัวเศษคือกรณีที่ทั้ง X และ Y เกิดขึ้นพร้อมกัน

สูตรนี้มาจาก ==conditional probability== ที่เคยเรียนมา:

$$P(B|A) = \frac{P(A \cap B)}{P(A)}$$

### ข้อควรระวังสำคัญ — Confidence ไม่สมมาตร

*(จาก transcript — อาจารย์ย้ำเป็นเรื่องสุดท้ายก่อนหมดเวลา)*

$$\text{Confidence}(X \rightarrow Y) \neq \text{Confidence}(Y \rightarrow X)$$

เหตุผล: **ตัวเศษเหมือนกัน แต่ตัวหารต่างกัน**

```
Confidence(Milk → Bread) = Support(Milk ∧ Bread) / Support(Milk)
Confidence(Bread → Milk) = Support(Milk ∧ Bread) / Support(Bread)
                            ^^^^^^^^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^
                            เหมือนกัน               ต่างกัน!
```

Support(X ∧ Y) กับ Support(Y ∧ X) เป็นสิ่งเดียวกัน (เพราะ "และ" สลับที่ได้) แต่ตัวหารเป็นคนละตัว ค่าที่ได้จึงไม่จำเป็นต้องเท่ากัน — **"การซื้อนมแล้วซื้อขนมปัง" ไม่เหมือนกับ "การซื้อขนมปังแล้วซื้อนม"**

## 10 Lift

==Lift== ตอบคำถามว่า **"ความสัมพันธ์นี้แข็งแรงกว่าความบังเอิญหรือเปล่า"**

$$\text{Lift}(X \rightarrow Y) = \frac{\text{Confidence}(X \rightarrow Y)}{\text{Support}(Y)} = \frac{\text{Support}(X, Y)}{\text{Support}(X) \times \text{Support}(Y)}$$

- ช่วงของค่า: **[0, +∞)**

### การตีความค่า Lift

| ค่า Lift | ความหมาย |
|---|---|
| **Lift > 1** | X และ Y เกิดขึ้นพร้อมกันบ่อยกว่าที่คาดไว้ถ้าทั้งสองเป็นอิสระต่อกัน → **มีความสัมพันธ์ที่แข็งแรง** |
| **Lift = 1** | X และ Y เป็นอิสระต่อกัน (independent) → **ไม่มีความสัมพันธ์กันเลย** |
| **Lift < 1** | X และ Y มีความสัมพันธ์เชิงลบ (negatively associated) → การมีตัวหนึ่ง **ลด** โอกาสของอีกตัว |

> ⚠️ **หมายเหตุ — สไลด์หน้า 6 พิมพ์ผิด** บรรทัดสุดท้ายเขียนว่า "Lift > 1: The items X and Y are negatively associated" ซึ่งขัดกับบรรทัดแรก ที่ถูกต้องคือ **Lift < 1** ตามที่ระบุในตารางข้างบน

*(จาก transcript)* อาจารย์บอกให้ **"อ่านผ่าน ๆ ได้ก่อน"** สำหรับ lift ในคาบนี้ เพราะถ้าใส่มากเกินไปจะจำไม่หมด ให้จำ support กับ confidence ให้แม่นก่อนเป็นอย่างน้อย

## 11 สูตรลัดทั้งสามตัว

สไลด์หน้า 7 สรุปสูตรทั้งสามในรูปที่ใช้ **frequency (จำนวนครั้งดิบ ๆ)** แทนที่จะใช้ support — ใช้แล้วสะดวกกว่าเวลาคำนวณด้วยมือ เพราะตัว N ตัดกันเอง

สำหรับกฎ **X ⟹ Y**:

$$\text{Support} = \frac{\text{Frequency}(X, Y)}{N}$$

$$\text{Confidence} = \frac{\text{Frequency}(X, Y)}{\text{Frequency}(X)}$$

$$\text{Lift} = \frac{\text{Support}}{\text{Support}(X) \times \text{Support}(Y)}$$

โดย **N = จำนวน transaction ทั้งหมด**

*(จาก transcript)* อาจารย์แนะนำให้จำเวอร์ชัน frequency เพราะจำง่ายกว่า และให้จำแค่ **2 ตัวบน (support, confidence)** ก่อน ส่วน lift ค่อยว่ากันทีหลัง

### ขยายไปใช้กับ 3 item

ถ้ากฎเปลี่ยนจาก X → Y เป็น X → Y ∧ Z ก็แค่**เพิ่ม Z เข้าไปในทุกที่ที่มี Y**:

$$\text{Confidence}(X \rightarrow Y, Z) = \frac{\text{Support}(X, Y, Z)}{\text{Support}(X)}$$

และถ้าเป็น A, B → C:

$$\text{Confidence}(A, B \rightarrow C) = \frac{\text{Support}(A, B, C)}{\text{Support}(A, B)}$$

| {Milk} | T1, T2, T3 | 3/3 = **100%** | Frequent ✅ |
| {Bread} | T1, T2 | 2/3 = **67%** | Frequent ✅ |
| {Butter} | T1 | 1/3 = **33%** | Infrequent ❌ **discard** |
| {Eggs} | T2, T3 | 2/3 = **67%** | Frequent ✅ |

**Frequent 1-itemsets: {Milk}, {Bread}, {Eggs}**

### Step 1b — นับ 2-itemset

จับคู่เฉพาะตัวที่รอดจากรอบก่อน (Butter ถูกตัดไปแล้ว จึงไม่ต้องนับคู่ใด ๆ ที่มี Butter — นี่คือ Apriori property ข้อ 2 ในการทำงานจริง)

| 2-itemset | ปรากฏใน | Support | ผล |
|---|---|---|---|
| {Milk, Bread} | T1, T2 | 2/3 = **67%** | Frequent ✅ |
| {Milk, Eggs} | T2, T3 | 2/3 = **67%** | Frequent ✅ |
| {Bread, Eggs} | T2 | 1/3 = **33%** | Infrequent ❌ **discard** |

**Frequent 2-itemsets: {Milk, Bread}, {Milk, Eggs}**

### Step 1c — หยุดที่นี่

ต้องหยุดเพราะ **ไม่มี 3-itemset ตัวไหนที่มี support ถึง 50% ได้** — {Milk, Bread, Eggs} ปรากฏใน T2 เท่านั้น คือ 1/3 = **33.33%** ต่ำกว่าเกณฑ์

### Step 2 — สร้าง association rules

จาก frequent itemset ที่ได้ สร้างกฎ if–then แล้วเช็ก confidence กับเกณฑ์ 75%

**จาก {Milk, Bread}:**

| กฎ | การคำนวณ | Confidence | ผล |
|---|---|---|---|
| **Rule 1:** {Milk} → {Bread} | Support({Milk, Bread}) / Support({Milk}) = (2/3) / (3/3) = 2/3 | **67%** | อ่อน ❌ **discard** (< 75%) |
| **Rule 2:** {Bread} → {Milk} | Support({Milk, Bread}) / Support({Bread}) = (2/3) / (2/3) | **100%** | **strong rule** ✅ |

Rule 2 บอกว่า **เมื่อไหร่ก็ตามที่มีคนซื้อขนมปัง เขาจะซื้อนมด้วยเสมอ**

**จาก {Milk, Eggs}:**

| กฎ | การคำนวณ | Confidence | ผล |
|---|---|---|---|
| **Rule 3:** {Milk} → {Eggs} | Support({Milk, Eggs}) / Support({Milk}) = (2/3) / (3/3) = 2/3 | **67%** | อ่อน ❌ **discard** |
| **Rule 4:** {Eggs} → {Milk} | Support({Milk, Eggs}) / Support({Eggs}) = (2/3) / (2/3) | **100%** | **strong rule** ✅ |

Rule 4 บอกว่า **เมื่อไหร่ก็ตามที่มีคนซื้อไข่ เขาจะซื้อนมด้วยเสมอ**

### กฎที่แข็งแรงสุดท้าย

1. **{Bread} → {Milk}** (Confidence = 100%)
2. **{Eggs} → {Milk}** (Confidence = 100%)

ข้อมูลนี้มีประโยชน์กับเจ้าของร้าน เช่นอาจวางนมไว้ใกล้กับโซนขนมปังและโซนไข่ เพื่อกระตุ้น ==impulse purchase==

### ตีความด้วย Lift — บทเรียนสำคัญที่สุดของตัวอย่างนี้

สังเกตว่าทั้งสองกฎมี confidence 100% ซึ่งดูดีมาก แต่พอคำนวณ lift:

$$\text{Lift}(\{Eggs\} \rightarrow \{Milk\}) = \frac{\text{Confidence}}{\text{Support}(\{Milk\})} = \frac{100\%}{100\%} = \mathbf{1}$$

$$\text{Lift}(\{Bread\} \rightarrow \{Milk\}) = \frac{100\%}{100\%} = \mathbf{1}$$

**Lift = 1 พอดี แปลว่าไม่มีความสัมพันธ์กันเลย**

เหตุผล: ที่ลูกค้าซื้อนมทุกครั้งที่ซื้อไข่ **ไม่ใช่เพราะไข่กับนมเกี่ยวข้องกัน แต่เพราะเขาซื้อนมในทุก transaction อยู่แล้ว** (Support({Milk}) = 100%) — confidence สูงจึงหลอกตาได้

ถ้า support ของนมต่ำกว่านี้ (เช่น 50%) แล้วยังได้ lift > 1 นั่นจึงจะบอกได้ว่ามีความสัมพันธ์ที่แข็งแรงจริงและไม่ใช่ความบังเอิญ

> **นี่คือเหตุผลว่าทำไม lift จึงเป็น metric ที่สำคัญในการค้นหา pattern ที่น่าสนใจจริง ๆ** — support กับ confidence อย่างเดียวไม่พอ

## 13 การจัดการกับ 3-itemset

สไลด์หน้า 16 และ 18–19 อธิบายเรื่องนี้

### หยุดที่ 2-itemset ได้ไหม

**ได้** — การหยุดที่ 2-itemset ถือว่าถูกต้องสมบูรณ์ แม้จะมี itemset ที่ใหญ่กว่าอยู่ก็ตาม เพียงแต่แปลว่าเราเลือกดูเฉพาะความสัมพันธ์แบบ ==pairwise== เท่านั้น ถ้าต้องการ bundle ที่ซับซ้อนขึ้นค่อยไปทำ 3-itemset

### กฎเหล็กของการสร้างกฎจาก 3-itemset

> **ทุกกฎต้องมี union ของ antecedent กับ consequent เท่ากับ itemset นั้นพอดี และทั้งสองฝั่งต้องไม่ว่าง — เมื่อสร้างกฎจาก frequent itemset ใด item ทุกตัวใน itemset นั้นต้องปรากฏในกฎ ไม่ว่าจะฝั่งซ้ายหรือฝั่งขวา ห้ามขาดตัวใดตัวหนึ่ง**

ดังนั้นถ้า frequent itemset คือ **{Milk, Bread, Butter}** จะสร้างกฎได้ **6 กฎ**:

**1. กฎที่มี 1 item ฝั่ง consequent (3 กฎ)**

| กฎ | Confidence |
|---|---|
| **Rule 1:** {Milk, Bread} → {Butter} | Support(Milk, Bread, Butter) / Support(Milk, Bread) |
| **Rule 2:** {Milk, Butter} → {Bread} | Support(Milk, Bread, Butter) / Support(Milk, Butter) |
| **Rule 3:** {Bread, Butter} → {Milk} | Support(Milk, Bread, Butter) / Support(Bread, Butter) |

**2. กฎที่มี 2 item ฝั่ง consequent (3 กฎ)**

| กฎ | Confidence |
|---|---|
| **Rule 4:** {Milk} → {Bread, Butter} | Support(Milk, Bread, Butter) / Support(Milk) |
| **Rule 5:** {Bread} → {Milk, Butter} | Support(Milk, Bread, Butter) / Support(Bread) |
| **Rule 6:** {Butter} → {Milk, Bread} | Support(Milk, Bread, Butter) / Support(Butter) |

สังเกตว่า **ตัวเศษเหมือนกันหมดทั้ง 6 กฎ** คือ Support ของ 3-itemset เต็ม ๆ ต่างกันแค่ตัวหาร

> **จุดที่มักผิด:** จาก 3-itemset {Milk, Bread, Butter} เรา **ไม่สามารถ** เขียนกฎว่า {Milk} → {Bread} ได้ เพราะ **Butter หายไป** — กฎนั้นเป็นกฎของ 2-itemset {Milk, Bread} ไม่ใช่ของ 3-itemset นี้

## 14 แบบฝึกหัด — dataset 5 transaction

สไลด์หน้า 17 ให้ทำแบบฝึกหัดจากตาราง 5 transaction ในหัวข้อ 05 ข้างบน โจทย์คือ **"Find association rules"**

*(จาก transcript)* อาจารย์ตั้งเกณฑ์ให้ทำในคาบว่า **min support = 60%** และ **min confidence = 80%** (โจทย์จริงในข้อสอบจะให้ threshold มาด้วยเสมอ ถ้าไม่ให้มาถือว่าโจทย์ยังไม่ครบ) ทำได้ไม่จบเพราะหมดเวลา — ข้างล่างนี้คือเฉลยที่ทำต่อจนจบ

**ข้อมูล:** T1 {Milk, Bread, Butter}, T2 {Milk, Diapers}, T3 {Bread, Butter, Diapers}, T4 {Milk, Bread, Butter}, T5 {Milk, Bread, Diapers} — **N = 5**

### Step 1a — 1-itemset (min support 60% = อย่างน้อย 3 จาก 5)

| 1-itemset | ปรากฏใน | Support | ผล |
|---|---|---|---|
| {Milk} | T1, T2, T4, T5 | 4/5 = **80%** | Frequent ✅ |
| {Bread} | T1, T3, T4, T5 | 4/5 = **80%** | Frequent ✅ |
| {Butter} | T1, T3, T4 | 3/5 = **60%** | Frequent ✅ (พอดีเกณฑ์) |
| {Diapers} | T2, T3, T5 | 3/5 = **60%** | Frequent ✅ (พอดีเกณฑ์) |

รอบนี้ผ่านหมดทั้ง 4 ตัว

### Step 1b — 2-itemset

จับคู่จาก 4 ตัวที่รอด ได้ทั้งหมด 6 คู่

| 2-itemset | ปรากฏใน | Support | ผล |
|---|---|---|---|
| {Milk, Bread} | T1, T4, T5 | 3/5 = **60%** | Frequent ✅ |
| {Milk, Butter} | T1, T4 | 2/5 = **40%** | ❌ discard |
| {Milk, Diapers} | T2, T5 | 2/5 = **40%** | ❌ discard |
| {Bread, Butter} | T1, T3, T4 | 3/5 = **60%** | Frequent ✅ |
| {Bread, Diapers} | T3, T5 | 2/5 = **40%** | ❌ discard |
| {Butter, Diapers} | T3 | 1/5 = **20%** | ❌ discard |

**Frequent 2-itemsets: {Milk, Bread}, {Bread, Butter}**

### Step 1c — 3-itemset และการ prune

candidate เดียวที่ประกอบจาก 2-itemset ที่รอดได้คือ **{Milk, Bread, Butter}** แต่ Apriori property ข้อ 2 ตัดทิ้งได้ทันทีโดยไม่ต้องนับเลย เพราะ subset ของมันคือ **{Milk, Butter} มี support แค่ 40% ซึ่งไม่ frequent**

(ถ้านับจริงจะได้ 2/5 = 40% ยืนยันว่า prune ถูกต้อง) → **ไม่มี frequent 3-itemset หยุดที่ 2-itemset**

### Step 2 — สร้างกฎ (min confidence 80%)

| กฎ | การคำนวณ | Confidence | ผล |
|---|---|---|---|
| {Milk} → {Bread} | 60% / 80% | **75%** | ❌ ไม่ผ่าน |
| {Bread} → {Milk} | 60% / 80% | **75%** | ❌ ไม่ผ่าน |
| {Bread} → {Butter} | 60% / 80% | **75%** | ❌ ไม่ผ่าน |
| {Butter} → {Bread} | 60% / 60% | **100%** | **strong rule** ✅ |

**กฎเดียวที่ผ่าน: {Butter} → {Bread} (Confidence = 100%)**

สังเกตว่า {Bread} → {Butter} ได้ 75% แต่ {Butter} → {Bread} ได้ 100% ทั้งที่มาจาก itemset เดียวกัน — **นี่คือตัวอย่างชัด ๆ ของความไม่สมมาตรของ confidence ที่อาจารย์ย้ำในหัวข้อ 09**

### เช็ก Lift

$$\text{Lift}(\{Butter\} \rightarrow \{Bread\}) = \frac{\text{Confidence}}{\text{Support}(\{Bread\})} = \frac{100\%}{80\%} = \mathbf{1.25}$$

**Lift = 1.25 > 1** แปลว่ากฎนี้มีความสัมพันธ์ที่แข็งแรงจริง ไม่ใช่ความบังเอิญ — ต่างจากตัวอย่างในหัวข้อ 12 ที่ได้ lift = 1 พอดี

(lift เป็นค่าที่สมมาตร ดังนั้น Lift({Bread} → {Butter}) = 75% / 60% = 1.25 เท่ากัน แม้ confidence จะต่างกัน)

| Transactional data | ข้อมูลที่บันทึกรายละเอียดของธุรกรรมหรือเหตุการณ์เดียวที่เกิดขึ้นจริงหนึ่งครั้ง |

| k-itemset | itemset ที่มีสมาชิก k ตัว เช่น 2-itemset คือ {Milk, Bread} |
| Frequent itemset | itemset ที่มี support มากกว่าหรือเท่ากับ minimum support threshold |
| Frequency | จำนวนครั้งดิบ ๆ ที่ itemset นั้นปรากฏ ยังไม่ได้หารด้วย N |
| Support | สัดส่วนของ transaction ที่มี itemset นั้นอยู่ ตอบว่า itemset นี้ popular แค่ไหน |
| Minimum support threshold | ค่าขั้นต่ำของ support ที่ผู้ใช้ตั้งไว้เอง ต่ำกว่านี้ถือว่า infrequent |

| Minimum confidence threshold | ค่าขั้นต่ำของ confidence ที่กฎต้องผ่านจึงจะถือว่าเป็น strong rule |
| Lift | อัตราส่วนที่บอกว่าความสัมพันธ์แข็งแรงกว่าความบังเอิญหรือไม่ มีค่าตั้งแต่ 0 ถึงอนันต์ |
| Strong rule | กฎที่ confidence ผ่านเกณฑ์ขั้นต่ำที่ตั้งไว้ |
| Antecedent | ฝั่งซ้ายของกฎ คือเงื่อนไข "ถ้า" ใช้สัญลักษณ์ A หรือ X |
| Consequent | ฝั่งขวาของกฎ คือผลลัพธ์ "แล้ว" ใช้สัญลักษณ์ C หรือ Y |
| Disjoint | สภาพที่ antecedent กับ consequent ไม่มี item ซ้ำกันเลย |
| Apriori algorithm | อัลกอริทึมหา frequent itemset และสร้าง association rules เสนอโดย Agrawal และ Srikant ปี 1994 |
| Apriori property | คุณสมบัติสองข้อ คือถ้า itemset frequent ทุก subset ก็ frequent และถ้าไม่ frequent ทุก superset ก็ไม่ frequent |
| Contrapositive | รูปสมมูลทางตรรกศาสตร์ที่ว่า p→q เท่ากับ ¬q→¬p ใช้อธิบาย Apriori property ข้อสอง |
| Subset | เซตย่อยที่สมาชิกทุกตัวเป็นสมาชิกของเซตแม่ |
| Superset | เซตที่ใหญ่กว่าซึ่งบรรจุ itemset ที่กำลังพิจารณาอยู่ข้างใน |
| Power set | เซตของทุก subset มีขนาด 2 ยกกำลัง n จึงต้องใช้ pruning ช่วยลดงานคำนวณ |
| Prune / discard | การตัด itemset ที่ไม่ frequent ทิ้ง เพื่อไม่ต้องขยายไปคำนวณ superset ของมัน |
| Impulse purchase | การซื้อโดยไม่ได้ตั้งใจล่วงหน้า เป็นเหตุผลที่ร้านค้าจัดวางสินค้าตาม association rules |
| Conditional probability | ความน่าจะเป็นแบบมีเงื่อนไข P(B|A) ซึ่งเป็นที่มาของสูตร confidence |

| Data science pipeline | แผนภาพที่แสดงว่าอะไรเข้า เกิดอะไรใน process และอะไรออกมาเป็นผลลัพธ์ |
| Live scoreboard | กระดานคะแนนของ Kaggle ที่ส่งโมเดลขึ้นไปแล้วได้ค่าความแม่นยำกลับมาทันที |
| IRB | คณะกรรมการจริยธรรมการวิจัยในมนุษย์ ต้องขออนุมัติก่อนเก็บข้อมูลจากอาสาสมัคร |
| PDPA | กฎหมายคุ้มครองข้อมูลส่วนบุคคล ข้อมูลสุขภาพและชีวมาตรถือเป็นข้อมูลอ่อนไหว |

## สรุปท้ายบท

| ประเด็น | สิ่งที่ต้องจำ |
|---|---|
| Association rules คืออะไร | กฎ if–then รูป X → Y ที่ได้จากข้อมูล transaction — อีกชื่อคือ association mining |
| MBA | Market Basket Analysis หาสินค้าที่ถูกซื้อพร้อมกัน ตัวอย่างคลาสสิกคือ beer & diapers |
| Transactional data | บันทึกเหตุการณ์เดียวหนึ่งครั้ง ควรมี timestamp — แต่ใน MBA ไม่สนใจจำนวนชิ้นและลำดับ |
| Itemset | เป็น set จึงไม่ซ้ำและไม่มีลำดับ — 1-itemset ใช้สร้างกฎไม่ได้ ต้องอย่างน้อย 2-itemset |
| ในทางปฏิบัติ | 3–4 itemset กำลังพอดี เกิน 5 ขึ้นไปหา pattern ยากและไม่มีประโยชน์ |
| Apriori property ข้อ 1 | ถ้า itemset frequent → ทุก subset ก็ frequent |
| Apriori property ข้อ 2 | ถ้า itemset ไม่ frequent → ทุก superset ก็ไม่ frequent (contrapositive ของข้อ 1) |
| ทำไมต้อง prune | power set มีขนาด 2ⁿ ถ้าสินค้ามีพันประเภทจะคำนวณไม่ไหว ต้องตัดตัวที่ไม่ frequent ทิ้งทันที |
| ขั้นตอน Apriori | 1-itemset → ตัดทิ้ง → 2-itemset → ตัดทิ้ง → 3-itemset → ตัดทิ้ง → หยุดเมื่อไม่เหลือ |
| **สูตร Support** | **Support(X) = จำนวน transaction ที่มี X ÷ จำนวน transaction ทั้งหมด** |
| **สูตร Confidence** | **Confidence(X→Y) = Support(X,Y) ÷ Support(X)** — มาจาก conditional probability |
| สูตร Lift | Lift(X→Y) = Confidence(X→Y) ÷ Support(Y) = Support(X,Y) ÷ [Support(X) × Support(Y)] |
| ที่ออกสอบแน่ | อาจารย์ย้ำว่า**ต้องเขียนสูตร support และ confidence ได้เอง** ข้อสอบไม่ให้สูตรมา ส่วน lift อ่านผ่านก่อนได้ |
| ตีความ Lift | > 1 สัมพันธ์แข็งแรง, = 1 เป็นอิสระต่อกัน, < 1 สัมพันธ์เชิงลบ (สไลด์หน้า 6 พิมพ์ผิดเป็น > 1) |
| กับดักของ confidence สูง | ตัวอย่างในสไลด์ได้ confidence 100% แต่ lift = 1 พอดี เพราะนมอยู่ในทุก transaction อยู่แล้ว — จึงต้องดู lift ด้วยเสมอ |
| Confidence ไม่สมมาตร | Confidence(X→Y) ≠ Confidence(Y→X) เพราะตัวเศษเหมือนกันแต่ตัวหารคนละตัว |
| กฎจาก 3-itemset | ได้ 6 กฎ (3 แบบ consequent 1 ตัว + 3 แบบ consequent 2 ตัว) ทุก item ต้องอยู่ในกฎครบ ห้ามขาด |
| หยุดที่ 2-itemset | ทำได้และถูกต้อง แค่แปลว่าเลือกดูเฉพาะความสัมพันธ์แบบ pairwise |
| ผลตัวอย่างในสไลด์ | min sup 50%, min conf 75% → strong rules คือ {Bread}→{Milk} และ {Eggs}→{Milk} ทั้งคู่ confidence 100% |
| ผลแบบฝึกหัด 5 transaction | min sup 60%, min conf 80% → strong rule เดียวคือ {Butter}→{Bread} confidence 100%, lift 1.25 |
| feedback โปรเจกต์ที่ย้ำที่สุด | dataset **ต้องมี label หรือ scoring** ไม่งั้น predict ไม่ได้ — เหลือแค่ทำ association หรือ clustering เท่านั้น |
| feedback รองลงมา | ต้องมี modeling ไม่ใช่แค่ filter, ต้องมี data science pipeline ที่ชัด, ต้องมี reference, ต้องบอกได้ว่าจะทดสอบอย่างไร |
| งานที่ต้องทำ | ดูตัวอย่าง advanced ที่อาจารย์อัปขึ้น Teams ช่วงเสาร์–อาทิตย์ + สัปดาห์หน้าคำนวณด้วยมือเทียบกับ Orange |
